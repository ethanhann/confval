New recorded constraints for the derive: `non_empty` and `length`.

{/* truncate */}

## Highlights

- `#[confval(non_empty)]` rejects an empty or whitespace-only string.
  On a list it also rejects a list with zero elements.
  The flag is a precondition on the value, so a field can carry it together with `keywords`, `range`, `length`, or `references`.
- `#[confval(length = ...)]` bounds the character count of a string.
  `length_constraint!` declares the bound with `max:` alone or with `min:` and `max:`, plus an optional `help:`.

## Added

- `#[confval(non_empty)]` on a `String` leaf or a string list.
  The derive runs the check during validation.
  The schema carries it as `SchemaField::non_empty`, a `bool` flag separate from the `Constraint` slot.
  The LSP hover renders "Must not be empty."
  The prelude exports `NON_EMPTY` and `NonEmptyConstraint` for a handwritten spec.
- `#[confval(length = PATH)]` on a `String` leaf, naming a `length_constraint!` const.
  The derive runs the check during validation.
  The schema carries it as `Constraint::Length` with numeric bounds.
  The LSP hover renders "Between 1 and 63 characters." or "At most 253 characters.", and the quick fix checks a default against the bound.
  The prelude exports `LengthConstraint` and `length_constraint!`.
  `length` is mutually exclusive with `range`, `keywords`, and `references`.
- The `textDocument/documentLink` handler in `confval-lsp`.
  A `Located<PathBuf>` field renders as a clickable link in the editor.
  The link target resolves relative paths against the document's directory.

## Upgrading

No breaking changes from 0.9.0.

```toml
[dependencies]
confval = { version = "0.10", features = ["derive", "hcl", "color"] }
```
