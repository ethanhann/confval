This release lets one language server process serve a configuration that spans several document shapes, lets a closed set of words apply to a list rather than only to a single value, and repairs a completion edit that could damage a list.

{/* truncate */}

## Highlights

### One server process for a multi document configuration

Some configurations span several document shapes: an entrypoint file, plus included files that carry their own root specs.
Until now each shape needed its own server process and its own editor registration, which duplicated your file patterns into editor config.

`serve_multi` serves every shape from one process.
You declare one binding per shape, pairing a matcher with the shape's root spec and its frontend, and the server picks the schema per document when the editor opens it.

```rust
use confval_lsp::{Matcher, bind, serve_multi, Hcl};

serve_multi(vec![
    bind::<EntrypointSpec, _>(Matcher::FileName("app.hcl".into()), Hcl),
    bind::<DevicesFile, _>(Matcher::Fn(Box::new(devices_matcher)), Hcl),
])
```

Bindings are tried in declaration order, and the first match wins.
A document that matches no binding stays open but gets no diagnostics and empty answers, with a warning log naming it.
A matcher must not panic, and on any problem it answers no match.
The server's panic guards need an unwinding runtime, so a build with `panic = "abort"` aborts instead.
`serve` answers every request as before and now runs as a one binding `serve_multi`, so a document with no file path, such as a never-saved buffer, keeps full service.
The one visible addition under `serve` is the routing log message each open now emits.

See the [language server guide](/docs/guide/language-server) for the routing rules and the matcher contract.

### A keyword set applies to a list

If a field accepts several words from a fixed vocabulary, you no longer write the check by hand (which required iterating over the list in a `Validate` trait implementation).
`#[confval(keywords = ...)]` now applies to a string list in both shapes.

```rust
#[derive(confval::Spec)]
struct LoggingSpec {
    #[confval(keywords = LogLevel)]
    level: Located<String>,
    #[confval(default, keywords = LogEvent)]
    events: Vec<Located<String>>,
    #[confval(keywords = LogPhase)]
    phases: Option<Located<Vec<Located<String>>>>,
}
```

The derive runs the check once for each element and reports a bad entry at that entry's own span, so a diagnostic
underlines the one word you need to change.
The set also reaches the schema, so an editor offers the same completions inside the list that it offers on a scalar.

`range` stays on a scalar leaf, because a list of numbers is not a field shape confval parses.
`references` stays on a scalar leaf, because the reference pass resolves one value against the labels in scope.

## Added

- `confval_lsp::serve_multi`, running one server process over a set of bindings.
- `confval_lsp::Router`, the server behind both entry points, constructible with `Router::new(bindings)` and runnable
  over any `lsp-server` connection, so an embedding host can own the connection.
- `confval_lsp::Binding` and `confval_lsp::bind`, pairing a matcher with a root spec and a frontend.
- `confval_lsp::Matcher` with the `Any`, `FileName`, and `Fn` variants.
- `confval_lsp::Validator`, the erased validate pass for one root spec.
- `confval_lsp::LspError` is exported, so both entry points return a nameable type.
- The server logs routing through `window/logMessage`: the matched binding at LOG level, an unmatched document at
  WARNING.
- `#[confval(keywords = ...)]` on `Vec<Located<String>>` and on `Option<Located<Vec<Located<String>>>>`.
- `SchemaType::scalar`, `SchemaType::string_list`, `SchemaType::block`, and `SchemaType::string_map`, the constructors
  a handwritten `ToSchema` builds with.
- `SchemaType::constraint`, which reads the constraint from a scalar or from a list's elements, so a reader renders one
  without naming both variants.

## Changed

- `confval_lsp::handlers::diagnostics` takes a `Validator` instead of the root spec type parameter.
  Replace `diagnostics::<S>(schema, ...)` with `diagnostics(Validator::of::<S>(), schema, ...)`.
  The function also computes the line index from the text it receives, so the `index` parameter is gone.
- `confval_lsp::serve`, `Server::new`, and `Server::run` require `F: Frontend + Send + 'static` and `S: 'static`.
  Every shipped frontend is a unit struct and every derived spec is `'static`, so this is observable only for a
  handwritten frontend or spec type that borrows, or a frontend that is not `Send`.
- `confval_lsp::Frontend` has `Debug` as a supertrait.
  Add `#[derive(Debug)]` to a handwritten frontend.
- `SchemaType::StringList` carries the constraint its elements declare.
- `SchemaType::StringList`, `SchemaType::Scalar`, and `SchemaType::Block` are marked `#[non_exhaustive]`, so a field
  added to any of them in a later release is no longer a break.

## Fixed

- Accepting a keyword completion inside a list replaced the whole list literal, which deleted the brackets and every
  other entry. The edit now replaces the one element under the cursor, and inserts at the cursor between elements and
  inside empty brackets.

## Upgrading

A handwritten frontend adds `#[derive(Debug)]`, and a direct `handlers::diagnostics` caller switches to
`Validator::of::<S>()`.
A single shape server that uses the shipped frontends and calls `serve` needs no code change.

The `SchemaType` variants take a rest pattern and build through a constructor.
A handwritten `ToSchema` needs both changes. 
A derived spec needs neither change.

```rust
// Before
SchemaType::StringList
SchemaType::Block { schema: Box::new(inner), repeated: false }

// After
SchemaType::string_list(None)
SchemaType::block(inner, false)
```

```rust
// Before
SchemaType::Scalar { leaf, constraint } => ...

// After
SchemaType::Scalar { leaf, constraint, .. } => ...
```
