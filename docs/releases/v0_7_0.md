This release adds a KDL frontend, three ways to print what a service loaded, and commented-out entries so a generated
template shows you every setting a spec accepts rather than only the ones that carry a value.

{/* truncate */}

## Highlights

### KDL joins HCL and TOML

The neutral field model was built so that a new format is another frontend over it.
KDL is the third, behind a `kdl` feature, with a parser and an emitter.
A node with only arguments is a value, a node with properties or children is a block, and `tls cert="a.pem"` and
`tls { cert "a.pem" }` reach the same `FromFields` impl.
Everything after the parse call is unchanged, which the `hcl`, `toml`, and `kdl` examples show by sharing every line
after their one format-specific call.

### Three representations from one loaded spec

An operator asking what the service is running wants three different answers, and confval now produces all three.

The source view, `ToFields::to_source_fields`, is the configuration as it was written, with defaults omitted.
It answers what was actually set.
A field is included when its `Located` span is attached, and a filled default carries the detached sentinel, so the span
decides.
Each included value keeps its real source span, so a location-aware consumer can find where it was written.

The populated view, `to_fields`, fills every default and answers what the service resolved to.
The runtime view is ordinary serde on the lowered config and answers what is running.

All three render through the existing emitters in any format.

### Templates show the settings you have not set

An absent optional field used to vanish from a generated template, doc comment included, so the template never told you
the setting existed.
`to_template` now renders each one as a commented-out entry with its doc comment above it.
The spelling is each format's own.
TOML and HCL prefix the entry with a spaceless `#`, and uncommenting is deleting that one character.
KDL uses its native slashdash, so the disabled node is part of the grammar rather than a convention layered on top of
it.

A commented entry is invisible to every parser, so a template parses to the same configuration with or without them.
`to_fields`, the plain dump, emits none.

## Added

- The `kdl` feature, with `parse_kdl`, `parse_kdl_fields`, and `emit_kdl`.
- Commented-out entries in `to_template`, along with `Field::commented` and `Field::as_commented` for a handwritten
  template walk.
- `ToFields::to_source_fields`, the source view described above.
- `ToFields::spec_doc` and `ToFields::type_doc`, and a struct-level `#[confval(doc = "...")]`.
  Template mode's doc source chain is now the field's `doc` attribute, then the field's rustdoc, then the embedded
  type's own doc, so a spec documented once at its definition annotates every site that embeds it.
- `FieldsBuilder`, `Walk`, and the sealed `Leaf` trait, for a handwritten `ToFields`.
  The builder takes the walk as a parameter, so an impl lists its fields once and both walks read that one list.
  The recursion into nested blocks follows the walk as well.
  `push` takes a field the builder does not shape, such as a string-keyed map.
  `Leaf` names the scalar types a field can hold, and no crate outside confval implements it, so the list can grow in a
  minor release.
- `Field::parsed`, the constructor a format frontend builds its fields with, and `Field::at`, which locates a
  constructed field.
- `Value::spanned`, the span-carrying value constructor.
- `parse_path_field`, which reads a `Located<PathBuf>` field.
  The derive now generates this call for that shape.
- `first_occurrence` and `parse_string_list_occurrence`, the helpers behind the repeated-field handling described under
  Changed.
- `KeywordSet::check_each`, and `narrow::keyword_list` and `narrow::opt_keyword_list`, for keyword list fields on the
  validation side and the lowering side.
- `keyword_enum!` now generates a `serde::Serialize` impl behind the `serde` feature, writing the keyword string so a
  serialized config spells `"log"` rather than the Rust variant name.

## Changed

- A repeated single-value field now reports a duplicate at the second occurrence, with a related span pointing at the
  first, and keeps the first value.
  It previously kept the last one silently.
  A list field accumulates its occurrences in document order instead.
  This is reachable through KDL, where repeated nodes are the natural list spelling, and through a hand-built `Fields`.
  HCL and TOML reject a repeated key in their own parsers, so a file in either format is unaffected.
- `parse_string_list_field` accepts a lone string as a one-element list, because a format with no array literal spells a
  one-element list as a single value.
  A lone `Scalar::Unparsed`, the kind an environment variable or a flag yields, stays a type mismatch.
- `emit_hcl` writes values before blocks at each level and puts a blank line above every block that follows another
  structure.
  This is the Terraform convention, and it matches the order TOML's syntax forces.
  It applies to every `emit_hcl` call rather than to templates alone.
- `Fields::get` and `Fields::has` skip a commented field, so one reads as absent everywhere.
  Only `Fields::iter` exposes one, which is what the emitters consume.
- `Field` is now `#[non_exhaustive]`.

## Upgrading

There are three breaking changes.

**`ToFields` gains a required method, `to_source_fields`.**
Every spec built with `#[derive(Spec)]` gets it generated, so no change is needed there.
A handwritten `ToFields` impl must add the method, returning the fields the source set.
Build both walks with `FieldsBuilder`, which takes the walk as a parameter and applies that rule per field, rather than
writing the span checks by hand.

**`Field` is `#[non_exhaustive]`, so a struct literal no longer compiles.**
This affects a frontend outside confval that builds its own fields.
Use `Field::parsed` on the read path, or `Field::detached_value` and `Field::detached_block` on the write path, then
attach what the shape needs through `with_doc`, `as_commented`, and `at`.
The marker is what makes the next field added to `Field` a minor release rather than another break.

**Enabling the `serde` feature adds a `Serialize` impl to every `keyword_enum!` type.**
A crate that already wrote its own `Serialize` for such an enum removes it.
Watch for this even if you did not enable `serde` yourself.
Cargo unifies features across the dependency graph, so another crate turning on confval's `serde` turns this impl on for
you, and the conflict surfaces as an error in your own code.

```toml
[dependencies]
confval = { version = "0.7", features = ["derive", "kdl", "color"] }
```
