The `non_empty` and `unique` flags take a help line.
A `format` records on a `PathBuf` field.
The reference pass is the one owner of label validity.
A handwritten spec builds its range and length records from the constants it checks with.

{/* truncate */}

## Highlights

- `#[confval(non_empty(help = "..."))]` and `#[confval(unique(help = "..."))]` keep a remediation line in the diagnostic, the schema, and the hover.
- `#[confval(format = AbsolutePath)]` compiles on a `Located<PathBuf>`.
- `#[confval(non_empty)]` on a `#[confval(label)]` field is a compile error, because `check_references` reports an empty label.

## Added

## Changed

- `check_references` treats a label of white space alone as empty.
  The empty label report has a help line that names the block and its label field.
  A reference to such a label no longer resolves.

## Removed

- The `#[confval(label, non_empty)]` pair.
  The derive rejects it with `#[confval(non_empty)] cannot be combined with #[confval(label)]; check_references reports an empty label, so run that pass beside validate_all`.

## Upgrading

If a `#[confval(label)]` field has `#[confval(non_empty)]`, delete the flag.
Confirm that your pipeline runs `check_references` beside `validate_all`, because that pass reports the empty label the flag reported.
If a config names a block with a label of spaces alone, that label now reports as empty and a reference to it reports as undefined.

```toml
[dependencies]
confval = { version = "0.12", features = ["derive", "hcl", "color"] }
```
