## Highlights

This release adds new macros to reduce boilerplate and introduce template generation.

## Added

### Template generation

The template generation feature allows a spec to be rendered back to a frontend format (TOML, HCL, or some future frontend).
It also allows for comments to be harvested from the spec's `///` comments or declared via a macro.

```rust
#[derive(confval::Spec)]
struct ServerSpec {
    #[confval(doc = "The address the server binds to.")]
    hostname: Located<String>,
    /// The port the server listens on.
    port: Located<i64>,
    /// The number of worker threads.
    #[confval(default = 4)]
    workers: Located<i64>,
    /// Whether TLS is enabled.
    #[confval(default = false)]
    tls: Located<bool>,
    /// Request size and mode limits.
    #[confval(nested, default)]
    limits: Option<Located<LimitsSpec>>,
}

fn parse_spec() -> Result<ServerSpec, String> {
    let spec: ServerSpec = confval::format::toml::parse_toml(&sources, id, &mut report)
        .ok_or("parse returned None without reporting an error")?;
    spec
}

fn print_plan_spec() -> Result<ServerSpec, String> {
    let spec = parse_spec()?;
    let text = confval::format::toml::emit_toml(&fields)
        .map_err(|error| error.to_string());
    print!("{text}");
}

/// Emit an annotated template...
/// The same configuration with each field's doc comment rendered above it, 
/// harvested from the spec's `///` comments.
fn print_annotated_spec() -> Result<ServerSpec, String> {
    let spec = parse_spec()?;
    let template = confval::format::toml::emit_toml(&spec.to_template())
        .map_err(|error| error.to_string())?;
    print!("{template}");
}
```

A note on comment precedence... if a Rust `///` comment and a doc macro exist, the macro is used and the comment is ignored.
For example, the comment in the config file for this spec would be "The address the server binds to.":

```rust
#[derive(confval::Spec)]
struct ServerSpec {
    #[confval(doc = "The address the server binds to.")]
    /// The comment is ignored.
    hostname: Located<String>,
}
```


### Manually lowering a keyword set to and enum is no longer required

`keyword_enum` declares a closed keyword set, its runtime enum, the TryFrom<&str> conversion, and the KeywordSet check in one place:

```rust
keyword_enum!(pub LimitMode, {
    Enforce => "enforce",
    Log     => "log",
    Off     => "off",
});
```

The macro expands to:

```rust
#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub enum LimitMode {
    Enforce,
    Log,
    Off,
}

impl LimitMode {
    pub const KEYWORDS: [&'static str; 1usize + 1usize + 1usize + 0usize] =
        ["enforce", "log", "off", ];

    pub const fn as_str(&self) -> &'static str {
        match self {
            Self::Enforce => "enforce",
            Self::Log => "log",
            Self::Off => "off",
        }
    }

    pub fn keyword_set() -> ::confval::KeywordSet<'static> {
        ::confval::KeywordSet::new(&["enforce", "log", "off", ])
    }
}

impl ::core::convert::TryFrom<&str> for LimitMode {
    type Error = ();

    fn try_from(value: &str) -> ::core::result::Result<Self, ()> {
        match value {
            "enforce" => ::core::result::Result::Ok(Self::Enforce),
            "log" => ::core::result::Result::Ok(Self::Log),
            "off" => ::core::result::Result::Ok(Self::Off),
            _ => ::core::result::Result::Err(()),
        }
    }
}

impl ::core::fmt::Display for LimitMode {
    fn fmt(&self, f: &mut ::core::fmt::Formatter<'_>) -> ::core::fmt::Result {
        f.write_str(self.as_str())
    }
}
```

Why this was added...

Every closed-set field maintained three separate manually synchronized artifacts:

1. A const slice of allowed strings (checked by KeywordSet during validation).
2. A runtime enum (used in the config type).
3. A TryFrom<&str> impl bridging the two at lowering.

### Automatically synchronize defaults

`derive_default` automatically generates `Default` impls from field-level confval attribute defaults, eliminating a manually synchronized duplicate.

Why this was added...

Defaults were declared twice.
Attribute defaults (#[confval (default = 16)]) fill absent fields during parsing, while a handwritten impl `Default` supplies the whole struct when an enclosing block is absent (consumed by #[confval (nested, default)] on the config side).
Nothing checks that the two agree.
Drift produced a subtle behavioral split between "block present but field omitted" and "block absent entirely."
